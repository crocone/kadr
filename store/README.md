# Store listing

Everything a submission needs, kept in the repository so it is reviewed like code and not
retyped into a form from memory.

One package goes to all three catalogues — `release/kadr-<version>.zip`, built by the
release workflow from a `v*` tag. Chrome Web Store also covers Yandex Browser, Brave and
Vivaldi: they install from CWS and Opera, and have no self-submission catalogue of their own.

## Texts

- [listing.en.md](listing.en.md) — English listing.
- [listing.ru.md](listing.ru.md) — Russian listing. Half of the audience arrives through
  Yandex Browser, so this one is not a translation afterthought.

Privacy policy (a required field): <https://crocone.github.io/kadr/privacy.html>, sources in
[`docs/`](../docs).

## Before submitting

- [ ] `npm run build` is green, and the tag matches the version in `package.json`.
- [ ] The listing texts below match what the build actually does — nothing promised early.
- [ ] Every permission has a justification (they are in the listing files).
- [ ] The privacy policy url resolves and mentions each request the extension can make.
- [ ] The source archive is attached to the GitHub release: review asks how the minified
      bundle was produced, and the answer is one link plus `npm ci && npm run build`.
